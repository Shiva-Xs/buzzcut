Add transitional options configuration and deprecation validator

Users need to opt into upcoming behavior changes ahead of major releases without breaking existing code. This adds a `transitional` options object and schema validator to support gradual migration.

### Behavior changes
- `silentJSONParsing`: defaults `true`; when `false` with `responseType: 'json'`, throws a SyntaxError `E_JSON_PARSE` on invalid JSON (#61)
- `forcedJSONParsing`: defaults `true` to auto-parse JSON strings; set `false` to prevent parsing when `responseType` is not json (#2791, #907)
- `clarifyTimeoutError`: defaults `false`; when `true`, emits `ETIMEDOUT` instead of `ECONNABORTED` on timeouts (#1543)
- Request encoding: stringifies primitive types when `Content-Type` is `application/json` (#2613)
- Transforms & XHR: invokes data transformers with `config` context; uses `onloadend` in the XHR adapter when available

### What's mechanical
- Adds `lib/helpers/validator.js` (~105 lines) to assert option types and log deprecation warnings based on package version.

Not tested: Run `npm test` across browser and Node environments.
