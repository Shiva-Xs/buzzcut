Add a provider-owned quarantine for invalid Claude receipt stores

Related to #280: for the `receipt_store_invalid_or_unavailable` teardown blocker, `/amux-claude` gets `quarantine plan|apply|inspect`, whose only action is the ordinary `amux worker park --thread <origin>`, so the worker can be parked without repairing or cleaning up provider evidence; core amux stays provider-neutral. The plan binds hashes of the exact origin, provider, action, executable, config, one store selector and up to 32 owner-supplied `0600` artifacts of at most 1 MiB; apply sets a permanent quarantine fence in `lifecycle.json` that blocks later launches, leaves every other file byte-identical, runs park from a sealed copy of the executable, and fails closed on evidence drift, conflicting replay, malformed metadata and interrupted parks, which are never retried. The focused quarantine test, the package tests, `go test ./...`, `go vet ./...`, gofmt, the build script and a privacy scan pass; tests use synthetic state and an injected park executor.
