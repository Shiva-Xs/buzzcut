Start nginx without the app upstream during the TLS bootstrap

`nginx/init-letsencrypt.sh` aborted the TLS bootstrap with "nginx failed to start — check nginx.conf for syntax errors", but the config was valid: started with `--no-deps`, nginx couldn't resolve `upstream app { server app:3000; }` and died with `[emerg] host not found in upstream "app:3000"`, and `nginx -t >/dev/null 2>&1` hid that. The script now swaps in a new port-80-only `nginx/nginx.bootstrap.conf` (the ACME webroot and a 404, no upstream, no TLS) under an `EXIT` trap that always restores `nginx.conf`, recreates the container so one left by a failed run picks up the swap, prints the `nginx -t` output and the last 50 log lines when the check fails, and afterwards stops and removes the bootstrap nginx instead of `docker compose down`, which would take the whole stack. The production `nginx.conf` is unchanged, since resolving `app` at runtime would cost the `keepalive` upstream pool. Not tested.
